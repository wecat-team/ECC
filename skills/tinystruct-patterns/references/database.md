# Lưu trữ cơ sở dữ liệu trong tinystruct

## Khi nào dùng

Dùng lớp dữ liệu kiểu ORM có sẵn cho các thao tác với cơ sở dữ liệu. Đây là lựa chọn nhẹ thay cho JPA/Hibernate, dùng các POJO kế thừa `AbstractData`, ánh xạ tới bảng bằng annotation hoặc file XML mapping.

## Cách hoạt động

### Kiến trúc

Mỗi bảng được biểu diễn bởi:
1. **Java POJO**: Kế thừa `AbstractData`, cung cấp getter/setter và `setData(Row)`.
2. **Mapping**, một trong hai:
   - **Annotation**: `@Table` trên class và `@Column` trên các field (xem [Annotation Mapping](#annotation-mapping)).
   - **Mapping XML**: `ClassName.map.xml` trong resources, gắn các field Java với các cột DB.

Mapping chỉ được đọc một lần cho mỗi class và được cache, nên việc tạo instance không bao giờ đọc hay parse lại, dù dùng cách nào. Nếu class có `@Table`, nó được ưu tiên hơn file `.map.xml` cùng tên.

#### Base class chính: `AbstractData`
Cung cấp các method CRUD:
- `append()` / `appendAndGetId()`
- `update()`
- `delete()`
- `findAll()` / `findOneById()` / `findOneByKey(key, value)`
- `findWith(where, params)`
- `find(SQL, params)`

### Sinh POJO (CLI)

Introspect một bảng trong database đang chạy để sinh POJO và mapping của nó: mặc định là file `.map.xml`, hoặc annotation ngay trên POJO.

#### Cấu hình
`application.properties`:
```properties
driver=com.mysql.cj.jdbc.Driver
database.url=jdbc:mysql://localhost:3306/mydb
database.user=root
database.password=secret
```

#### Lệnh
```bash
# Interactive mode
bin/dispatcher generate

# Specify table
bin/dispatcher generate --tables users

# Annotate the POJO instead of writing a .map.xml file
bin/dispatcher generate --tables users --mapping annotation
```

`--mapping` nhận `xml` (mặc định) hoặc `annotation`. Ở chế độ annotation, không có file `.map.xml` nào được ghi và không tạo thư mục resources. Giá trị không hợp lệ bị từ chối trước khi hiện bất kỳ prompt nào.

## Ví dụ

### Các thao tác CRUD
```java
// CREATE
User user = new User();
user.setUsername("james");
user.append();

// READ
User user = new User();
user.setId(42);
user.findOneById();

// UPDATE
user.setEmail("new@example.com");
user.update();

// DELETE
user.delete();
```

### Truy vấn có điều kiện
```java
User user = new User();
Table results = user.findWith("username LIKE ?", new Object[]{"%jam%"});

// Fluent Condition Builder
Condition condition = new Condition();
condition.setRequestFields("id,username");
Table filtered = user.find(
    condition.select("`users`").and("email LIKE ?").orderBy("id DESC"),
    new Object[]{"%@example.com"}
);
```

### Cấu trúc Mapping XML
`User.map.xml`:
```xml
<mapping>
  <class name="User" table="users">
    <id name="Id" column="id" autoIncrement="true" autoGenerated="false" length="11" type="int"/>
    <property name="username" column="username" length="50" type="varchar"/>
    <property name="email" column="email" length="100" type="varchar"/>
  </class>
</mapping>
```

### Annotation Mapping
Cùng class `User` được ánh xạ bằng annotation (đây là kết quả của `generate --mapping annotation`):
```java
import org.tinystruct.data.annotation.Column;
import org.tinystruct.data.annotation.Id;
import org.tinystruct.data.annotation.Table;

@Table(name = "users",
        id = @Id(name = "Id", column = "id", type = "int", length = 11, autoIncrement = true))
public class User extends AbstractData implements Serializable {
    @Column(name = "username", type = "varchar", length = 50)
    private String username;

    @Column(name = "email", type = "varchar", length = 100)
    private String email;

    // getters, setters (using setFieldAsXxx) and setData(Row) as usual
}
```

| Annotation | Đặt trên | Thuộc tính |
|---|---|---|
| `@Table` | class | `name` (bắt buộc), `schema` (mặc định không có), `id` (mặc định: không có identifier) |
| `@Id` | bên trong `@Table(id = ...)` | `name` (mặc định `Id`), `column`, `type`, `length`, `autoIncrement`, `autoGenerated`. `column` rỗng nghĩa là bảng không có identifier. |
| `@Column` | field | `type` (bắt buộc), `name` (cột DB; mặc định là tên field Java), `length` |

- Identifier được mô tả bên trong `@Table` vì nó được kế thừa từ `AbstractData`; không có field riêng nào của bạn để gắn annotation.
- `type` nhận cùng các tên như thuộc tính XML `type` (các tên `FieldType`, so khớp không phân biệt hoa thường): `INT`, `BIGINT`, `VARCHAR`, `TEXT`, `DATE`, `TIMESTAMP`, v.v.
- Chỉ các field có `@Column` mới được ánh xạ. `@Table` được kế thừa, và các field có annotation của superclass cũng được ánh xạ.
- Ánh xạ cùng một property hai lần, ví dụ field của subclass che (hide) một field có annotation của superclass, sẽ gây lỗi ở lần đầu tiên class được sử dụng.
- `autoGenerated = true` cấp một UUID mới cho id không phải số nguyên với mỗi instance mới; `autoIncrement = true` để database tự quyết định giá trị.
- Phần tử `<id>` của file `.map.xml` dùng cùng các tên này, `autoIncrement` và `autoGenerated`. Các file viết với thuộc tính cũ `increment` và `generate` vẫn hoạt động; nếu có cả hai cách viết thì cách mới được ưu tiên.

### Tự động tạo bảng
Thêm một dòng vào `application.properties` để các bảng còn thiếu được tạo tự động:
```properties
database.autocreate=true
```

- **Mặc định tắt.** Không có gì chạm vào schema của bạn trừ khi bạn bật tùy chọn này, và khi đó user database cần có quyền `CREATE`.
- Lần đầu một class đã ánh xạ được khởi tạo, bảng của nó được tạo nếu chưa tồn tại. Việc này xảy ra một lần cho mỗi class trong mỗi process, hoạt động với cả annotation lẫn XML mapping, và không tốn thêm chi phí cho các instance sau.
- Đó là một câu lệnh duy nhất, an toàn khi nhiều instance khởi động cùng lúc: `CREATE TABLE IF NOT EXISTS` (SQL Server dùng guard `OBJECT_ID` thay thế).
- Cột `@Id` trở thành primary key, với cú pháp auto-increment hoặc identity riêng của database khi `autoIncrement = true`.
- Kiểu cột được render thành kiểu native của database đích, ví dụ `TIMESTAMP` thành `DATETIME` trên MySQL và `DATETIME2` trên SQL Server, `TEXT` thành `VARCHAR(MAX)` trên SQL Server, và `BLOB` thành `BYTEA` trên PostgreSQL. `VARCHAR` không có length sẽ được gán 255.
- Lỗi (ví dụ thiếu quyền) được ghi log dưới dạng cảnh báo và không bao giờ ngăn việc tạo object; câu lệnh thực sự đầu tiên sau đó sẽ báo lỗi gốc của database.

Các giới hạn cần lưu ý:
- Cột `DECIMAL` được tạo không có precision hoặc scale, vì mapping chỉ mang một giá trị `length` duy nhất.
- Kiểu cột không nằm trong các tên `FieldType` sẽ bị từ chối.
- Chỉ tạo bảng, cột và primary key. Không có index, foreign key, default hay `NOT NULL` cho các cột khác.
- Bảng đã tồn tại không bao giờ bị alter hay migrate, kể cả khi khác với mapping.
- Redis không có bảng và không được hỗ trợ.

## Quy tắc quan trọng

1. **Vị trí file** (chỉ với XML mapping): Mapping XML **PHẢI** phản chiếu đường dẫn package của POJO dưới `src/main/resources/`.
2. **Đặt tên**: Tên bảng được singularize thành tên class (`users` → `User`). Cột có gạch dưới trở thành field camelCase (`created_at` → `createdAt`).
3. **Setter**: Dùng các method `setFieldAsXxx` (ví dụ `setFieldAsString`) trong setter để đồng bộ trạng thái với field map nội bộ.
4. **Field Id**: Field khóa chính trong Java luôn tên là `Id` (kế thừa từ `AbstractData`).
5. **Một nguồn mapping**: Dùng annotation hoặc XML cho một class, không dùng cả hai. Nếu có cả hai, annotation được ưu tiên và XML bị bỏ qua.
